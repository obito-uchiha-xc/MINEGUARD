## 1. Phase Objective

Implement a clean, robust, and extensible persistent data layer for the Integrated Mine Safety Monitoring System using PostgreSQL compatibility, modern SQLAlchemy 2.0 ORM, and Alembic migrations.

---

## 2. Database Architecture & Technologies

- **Database Engine**: PostgreSQL as primary production target (`postgresql+psycopg://...`); SQLite with `aiosqlite` for local dev/testing (`sqlite+aiosqlite://...`).
- **ORM**: SQLAlchemy 2.0 modern declarative mapping (`Mapped`, `mapped_column`, `relationship(lazy="selectin")`).
- **Session Management**: Asynchronous session factory via `async_sessionmaker` and FastAPI dependency `get_db_session()`.
- **Migration Framework**: Alembic with autogenerated, reversible migrations supporting batch alter operations for cross-database portability.

## 3. Implemented Data Model & Hierarchy

The domain model faithfully realizes the physical-to-sensor hierarchy established in Phase 0:

$$\text{Mine} \xrightarrow{\text{1:N}} \text{Zone} \xrightarrow{\text{1:N}} \text{IntegratedNode} \xrightarrow{\text{1:N}} \text{Sensor} \xrightarrow{\text{1:N}} \text{SensorReading}$$

```
┌──────────────────────────────────────────────────────────┐
│                         MINES                            │
│  id (PK) | name (Unique) | code (Unique) | created_at    │
└────────────────────────────┬─────────────────────────────┘
                             │ 1:N (Cascade Delete)
                             ▼
┌──────────────────────────────────────────────────────────┐
│                         ZONES                            │
│  id (PK) | mine_id (FK) | name | code | created_at       │
└────────────────────────────┬─────────────────────────────┘
                             │ 1:N (Restrict Delete)
                             ▼
┌──────────────────────────────────────────────────────────┐
│                    INTEGRATED_NODES                      │
│  id (PK) | zone_id (FK) | node_identifier (Unique)       │
│  status | last_seen_at | created_at                      │
└────────────────────────────┬─────────────────────────────┘
                             │ 1:N (Cascade Delete)
                             ▼
┌──────────────────────────────────────────────────────────┐
│                        SENSORS                           │
│  id (PK) | node_id (FK) | sensor_type (Extensible String)│
│  sensor_identifier | unit (TBD) | is_active | created_at │
└────────────────────────────┬─────────────────────────────┘
                             │ 1:N (Restrict Delete)
                             ▼
┌──────────────────────────────────────────────────────────┐
│                    SENSOR_READINGS                       │
│  id (PK) | sensor_id (FK) | node_id (FK)                 │
│  timestamp (UTC) | value (Float) | created_at            │
│  Indexes: (node_id, timestamp), (sensor_id, timestamp)   │
└──────────────────────────────────────────────────────────┘
```

## 4. Entity Detail & Field Mappings

### 4.1 `Mine` (`mines`)
- `id`: Integer Primary Key.
- `name`: Unique String(255) (e.g., "Apex Deep Shaft").
- `code`: Unique String(64), nullable.
- `created_at`: UTC timestamp.
- **Relationship**: 1-to-many with `Zone` (cascade on delete).

### 4.2 `Zone` (`zones`)
- `id`: Integer Primary Key.
- `mine_id`: Foreign Key to `mines.id` (CASCADE).
- `name`: String(255) (e.g., "Zone A", "Zone B" per Sec. 9).
- `code`: String(64), indexed.
- `created_at`: UTC timestamp.
- **Relationship**: 1-to-many with `IntegratedNode` (RESTRICT on delete).

### 4.3 `IntegratedNode` (`integrated_nodes`)
- `id`: Integer Primary Key (internal surrogate).
- `zone_id`: Foreign Key to `zones.id` (RESTRICT).
- `node_identifier`: Unique String(128) (external physical identifier, format marked TBD).
- `status`: String(32), indexed, default `"ACTIVE"` (supports `UNRESPONSIVE` detection for BE-REQ-023).
- `last_seen_at`: UTC timestamp, nullable (tracks latest packet for heartbeat timeout).
- `created_at`: UTC timestamp.
- **Relationship**: 1-to-many with `Sensor` and `SensorReading`.

### 4.4 `Sensor` (`sensors`)
- `id`: Integer Primary Key.
- `node_id`: Foreign Key to `integrated_nodes.id` (CASCADE).
- `sensor_type`: String(64), indexed (extensible string accommodating displacement, vibration, cracks, temperature, humidity, pressure, CH4, CO, O2, and other gases).
- `sensor_identifier`: String(64), optional channel/sub-sensor tag.
- `unit`: String(32), nullable (marked TBD; no units hard-coded).
- `is_active`: Boolean, default `True`.
- `created_at`: UTC timestamp.
- **Relationship**: 1-to-many with `SensorReading` (RESTRICT on delete).

### 4.5 `SensorReading` (`sensor_readings`)
- `id`: Integer Primary Key.
- `sensor_id`: Foreign Key to `sensors.id` (RESTRICT).
- `node_id`: Foreign Key to `integrated_nodes.id` (RESTRICT; direct FK for fast node-wise queries).
- `timestamp`: UTC DateTime (observation timestamp).
- `value`: Float precision numerical reading.
- `created_at`: UTC DateTime (database insertion timestamp).
- **Composite Indexes**:
  - `ix_sensor_readings_node_timestamp` on `(node_id, timestamp)`
  - `ix_sensor_readings_sensor_timestamp` on `(sensor_id, timestamp)`
  - Single index on `timestamp`

## 5. Deletion & Retention Invariants

- **Safety Audit Invariant**: Historical telemetry records (`sensor_readings`) cannot be deleted by cascading parent deletes (`ondelete="RESTRICT"`). Telemetry remains an immutable audit trail.
- **Node Protection Invariant**: Active nodes cannot be accidentally deleted by dropping a zone without reassigning or decommissioning them.
- **Retention Policy**: Undefined in project overview; marked as **TBD** (no automatic purge or TTL logic implemented).
